# Plan

Create a hard variant of the challenge.

# Context

The current version of the challenge hands the competitors almost everything
they need to build the optimal solution based on the epistemic reject option.
Specifically, the competitors get:

- the training prior and the set of test priors, given explicitly;
- an explicit statement that the problem is prior (label-shift) adaptation;
- the formula for adapting the plug-in Bayes predictor when the training and
  test priors are known;
- a pre-trained model with a well-calibrated posterior.

As a result, a single step separates the competitors from the optimal
epistemic reject-option predictor.

The goal of the hard variant is a challenge in which the competitors must
discover most of the steps on their own, and the optimal solution requires
several of them. This is meant to simulate a real-life setting.

# Changes

For each item below, *told* is what the competition description says and
*actually* is the underlying ground truth, known only to the organisers.

## Problem definition

**Told.** The training data were collected at $L=9$ locations, e.g. $L$ hospitals or labs. All locations capture images with the same device, but the
class frequencies may differ considerably between locations.

**Actually.** Each location corresponds to one label prior, so the problem is
still label-prior shift. The competitors must realise on their own that the
per-location priors can be estimated from the class frequencies in the
training data of that location.

## Evaluation metric

**Told.** The evaluation metric is defined exactly as in the current version, and its precise formula is given. The reference predictor, however, is described only in words:

> The reference predictor for a given location was trained on the same
> training data as provided to the competitors and then fine-tuned to maximise
> performance at that location. The reference predictors themselves are not
> released; the competitors only get their predictions on the development data.

**Actually.** The reference predictor is, as before, the plug-in Bayes
predictor adapted to the true prior of the location. Neither its formula nor
the underlying model is disclosed.

The underlying model is a single CNN trained by the existing pipeline
(`train_base_model.py`), run on the new training data with the location
labels ignored:

1. The training data are split, stratified by class, into a weight-fitting
   part and a validation part. Because of the stratification, both parts have
   the pooled class distribution of the training data, $\pi_{\rm tr}$.
2. The CNN weights are fitted on the weight-fitting part. The epoch is
   selected on the validation part.
3. The posterior is calibrated (BCTS) on the same validation part. The
   calibrated posterior is therefore the posterior under $\pi_{\rm tr}$.
4. For a location $\ell$ with prior $\pi_\ell$, the posterior is adjusted from
   $\pi_{\rm tr}$ to $\pi_\ell$, and the plug-in Bayes rule is applied.

## Parameter prior

**Told.** When describing the test data, the description states that every
location contributed the same number of test batches.

**Actually.** The parameter prior (the probability of generating a test batch
from a given location) is uniform, as before, but this is never stated
explicitly.

## Data split

Unlike the current version, the competitors get the images. The TissueMNIST
dataset is split into three parts:

1. **Training data** — labelled images, each assigned to one of the $L$
   locations.
2. **Development data** — images organised into batches. Each image comes with
   its true label and the prediction of the reference predictor.
3. **Test data** — images organised into batches. The true labels and the
   reference predictions are kept by the organisers for scoring and are not
   released.

The test data consist of the original TissueMNIST validation and test splits. The original training split is divided into the training data and the development data, with the development data taking about 10 % of it.

Batches in the development data and in the test data are generated by the same procedure.

### Assigning the training data to locations

All of the training data are assigned to locations; none are discarded.
Locations $1,\dots,8$ start from the 8 priors in
`priors_tissuemnist_challenge.txt`. Location 9 takes every remaining
training image, so its prior is the class distribution of that remainder.
Locations do not need to have the same number of images.

**Why the priors must change.** In each of the 8 priors, every class gets 0.35
twice and 0.05 six times, so the class probabilities summed over the 8
locations equal exactly 1.0 for every class. A location of size $n_\ell$ needs
$0.35\,n_\ell$ or $0.05\,n_\ell$ images of each class. The rarest class
(Glomerular endothelial cells) has only 5,279 images in the training data
(90 % of the original training split). With the priors unchanged:

- each of locations 1–8 can hold at most about 5,279 images;
- location 9 gets zero probability for the Glomerular class.

Class probabilities of exactly zero are not allowed, so the priors are adjusted
as little as possible.

**Procedure.** Let $n_\ell$ be the size of location $\ell$ and $m_{\ell c}$ the
number of its images of class $c$. Every constraint below is linear in $m$ and
$n$, so the problem is a linear program for a fixed $\delta$:

- all training data are used: $\sum_{\ell \le 9} m_{\ell c} = D_c$ for each
  class $c$, where $D_c$ is the number of training images of class $c$;
- floor on the priors: $m_{\ell c} \ge \varepsilon\, n_\ell$ for all 9
  locations;
- minimum location size: $n_\ell \ge n_{\min}$ for $\ell \le 8$;
- limited change: for $\ell \le 8$, the total-variation distance between the
  new prior $m_{\ell\cdot}/n_\ell$ and the original prior is at most $\delta$.

Take the smallest $\delta$ for which a solution exists (bisection over
$\delta$), and among those solutions maximise $\min_{\ell \le 8} n_\ell$. Then
round the $m_{\ell c}$ to integers, write the new priors back to the priors
file (all 9 locations), and check that the pairwise TV guard still holds.

**Choosing the parameters.** The floor $\varepsilon$ has to be below the
share of the rarest class, 0.0355. With all data used, no set of priors can
give every location ≥ 0.05 on it. A preliminary run of the linear program
shows the trade-off:

| $\varepsilon$ | $n_{\min}$ | max TV change $\delta$ | $n_\ell$, locations 1–8 | Location 9 | Min pairwise TV |
| --: | --: | --: | --: | --: | --: |
| 0.01 | 5,000 | **0.03** | 5,573 | 104k (70 %) | 0.29 |
| 0.01 | 8,000 | 0.12 | 8,210 | 83k (56 %) | 0.30 |
| 0.01 | 10,000 | 0.19 | 10,191 | 67k (45 %) | 0.23 |
| 0.02 | 5,000 | 0.10 | 5,001 | 109k (73 %) | 0.23 |

**Recommended:** $\varepsilon = 0.01$, $n_{\min} = 5000$. The 8 priors change
by at most 0.03 in TV (mostly by lowering the Glomerular class from 0.05 to
0.02). Location 9 gets roughly
$\pi_9 \approx (0.40, 0.01, 0.01, 0.08, 0.05, 0.01, 0.29, 0.16)$, which is at
TV ≈ 0.14 from the pooled training prior, so batches from location 9 are also
shifted. Location 9 holds about 70 % of the training data. That is harmless:
the test batches are spread evenly over locations regardless of their training
size.

## Preventing label recovery

Releasing the images while disclosing that they come from TissueMNIST makes it
possible to cheat by recovering the true labels of the test images. This is
addressed in two ways:

1. **Rules.** The challenge rules explicitly prohibit using any data or
   information other than what is provided, and explicitly prohibit any
   attempt to recover the true labels of the test data.
2. **Image transformation.** All released images (training, development and
   test alike) are transformed as follows:
   - each image is randomly rotated by 90, 180 or 270 degrees;
   - low-amplitude noise is added to the pixels. The noise has a negligible effect on image quality but defeats exact matching against the original dataset. It will be Gaussian noise with small variance (the actual variance need to be tune in order not to harm the prediction)

Neither measure prevents cheating completely; together they make it harder.
