# Dataset description

Every test image in this competition arrives as part of a **batch**, and each
batch was drawn under its own unknown mix of the eight classes. Your job is to
label each image *and* to say how much you trust each label.

## What you are predicting

For **every row** of `test_batches.csv` you submit two things:

* `pred` — the class label, an integer `0`–`7`
* `confidence` — a real number saying how much the prediction should be trusted

You are **not** asked to reject anything yourself. The organisers sort all
predictions of the same batch size by descending `confidence`, keep the most
confident 80 %, and score only those. So `confidence` decides *which* of your
predictions count.

## The setting, in plain terms

The images are human kidney cortex cells, 28×28 pixels, greyscale, in 8 tissue
classes. A convolutional network was trained on a set of images you never see,
and its output is given to you in `predictions.csv`.

The catch is that the network was trained on a **different mix of classes** than
the test batches were drawn from. Concretely:

* Each test batch was generated by first picking one **class prior** — a vector
  of 8 probabilities summing to 1 — and then drawing that batch's images
  independently according to it.
* The prior of every batch is one of the **8 rows of `test_priors.csv`**, chosen
  uniformly at random and independently for each batch. Nothing else is
  possible: those 8 rows are the complete list.
* The **class-conditional appearance does not change.** A "Leukocytes" image in a
  test batch is drawn from the same population of Leukocytes images the network
  saw. Only *how often* each class occurs changes.
* The mix the network was trained on is in `train_prior.csv`. It is **not** one
  of the 8 test priors — every test batch is shifted relative to training.

The images in a batch are the only evidence you have about which of the 8 priors
that batch used. Batches range from 1 image (no useful evidence) to 100.

## Files

### The test set

* **`images/`** — 66,217 PNG files, 28×28, 8-bit greyscale. Filenames are random
  hex strings and carry no information.
* **`test.csv`** — one row per test batch: 12,600 batches.
* **`test_batches.csv`** — one row per test image: 126,000 rows. Says which batch
  each image belongs to and where to find the PNG.
* **`sample_submission.csv`** — a valid submission in the correct format,
  produced by the network alone with no use of the batch. It is the baseline to
  beat.

Batch sizes and counts:

| batch size `m` | 1 | 2 | 5 | 10 | 20 | 50 | 100 |
| :-- | --: | --: | --: | --: | --: | --: | --: |
| number of batches | 6,000 | 3,000 | 1,200 | 600 | 600 | 600 | 600 |
| images in total | 6,000 | 6,000 | 6,000 | 6,000 | 12,000 | 30,000 | 60,000 |

### What the network gives you

* **`predictions.csv`** — the trained network's calibrated output for **every**
  released image (66,217 rows), both test and development. Row `img` gives
  `p0`…`p7`, the probability of each class **under the training mix**. You may
  use this directly; you do not have to run the network yourself.
* **`train_prior.csv`** — one row: the class frequencies the network was trained
  on.
* **`test_priors.csv`** — the 8 admissible test priors, one per row. Each test
  batch used exactly one of them, drawn uniformly at random.

### For scoring yourself offline

You cannot score yourself on the test set — those labels are not in the data.
Instead you get a second, fully labeled set of batches built the same way:

* **`dev.csv`** — 16,547 labeled development images (`img`, `label`). These
  images appear nowhere in the test batches.
* **`dev_test.csv`** — 1,050 development batches, same size grid as the test set.
* **`dev_test_batches.csv`** — one row per development test image: 10,500 rows.
* **`dev_solution.csv`** — the answers for those 10,500 rows: the true label and
  the reference predictor's label, plus each row's batch size.
* **`dev_sample_submission.csv`** — the baseline, on the development batches.

Run your predictor on `dev_test_batches.csv`, then score the result against
`dev_solution.csv` with the `evaluate.py` in the starter code. The number it
prints is computed by the same function the leaderboard uses. The development
set is smaller than the test set, so its scores are noisier — do not read small
differences as real.

## Columns

### `test_batches.csv` and `dev_test_batches.csv`

* `row_id` — identifies one test image. **This is the key your submission must
  use.** Globally unique.
* `id_test` — which batch the image belongs to. All images sharing an `id_test`
  were drawn under the same prior.
* `slot` — the image's position in its batch, `0` to `m-1`. **The order is
  arbitrary and carries no information.**
* `img` — path to the PNG, e.g. `images/db18bc294e4c680e00882c19e613f481.png`.

### `test.csv` and `dev_test.csv`

* `id_test` — the batch.
* `m` — how many images the batch contains.

### `sample_submission.csv` and `dev_sample_submission.csv`

* `row_id` — as in `test_batches.csv`; one row for every test image.
* `pred` — predicted label, integer `0`–`7`.
* `confidence` — any finite real number; larger means "keep this prediction".

### `predictions.csv`

* `img` — path to the PNG, matching `test_batches.csv` and `dev.csv`.
* `p0` … `p7` — the network's calibrated probability of each class **under the
  training mix**. Each row sums to 1.

### `test_priors.csv`

* `id` — prior id, `0`–`7`.
* `p0` … `p7` — the probability of each class under that prior. Each row sums
  to 1.

### `train_prior.csv`

* `p0` … `p7` — the class frequencies the network was trained on. One row.

### `dev.csv`

* `img` — path to the PNG.
* `label` — the true class, `0`–`7`.

### `dev_solution.csv`

* `row_id`, `id_test`, `slot` — as in `dev_test_batches.csv`.
* `m` — the batch size, repeated on every row for convenience.
* `label` — the true class.
* `pred_ref` — the label predicted by the **reference predictor**, which was
  told that batch's true prior. The metric measures how much more often your
  `pred` is wrong than this column is.

## The classes

| label | tissue |
| --: | :-- |
| 0 | Collecting Duct, Connecting Tubule |
| 1 | Distal Convoluted Tubule |
| 2 | Glomerular endothelial cells |
| 3 | Interstitial endothelial cells |
| 4 | Leukocytes |
| 5 | Podocytes |
| 6 | Proximal Tubule Segments |
| 7 | Thick Ascending Limb |

Classes 2 and 3 are close to indistinguishable at 28×28. Some error is
irreducible, and the metric is built to account for that: it compares you
against a reference predictor working from the same network output, not against
perfection.

## Five things that cost people points

**`confidence` is a ranking, not a probability.** Any strictly increasing
transformation of your confidences gives exactly the same score. What matters is
that your likely-wrong predictions sit at the bottom.

**Confidences are pooled across batches.** Within one batch size, every image
from every batch of that size goes into a single ranking. A batch whose prior
you could not pin down should therefore carry *uniformly lower* confidence than
one you could. Normalising confidences inside each batch throws that away.

**Ties are broken by ascending `row_id`.** A constant `confidence` column is
scored deterministically, and badly.

**An image can appear more than once in a batch.** Batches are drawn with
replacement, so a repeat is normal and is not a mistake in the data. The same
image may also appear in several different batches.

**Every row needs an answer.** Your submission must contain exactly one row for
each `row_id` in `test_batches.csv`, with a whole number `0`–`7` in `pred` and a
finite number in `confidence`. There is no way to abstain in the file format.

## Words used here

* **prior** — the vector of 8 class probabilities a batch was drawn from.
* **label shift** — the situation in this competition: the mix of classes
  changes between training and test, but what each class looks like does not.
* **coverage** — the fraction of your predictions that are kept and scored,
  fixed at 80 %.
* **regret** — how much more often your kept predictions are wrong than the
  reference predictor's. Lower is better, and it can be negative.
